Shipping a browser extension in a weekend

From the first idea to the store listing in 48 hours — and why the screenshots took longer than the code.

Alex Moreau · 7 min read · Updated last week
1280 × 800

Every side project starts the same way: a small annoyance, a free weekend and the firm belief that this time it will be quick. Mine was a tiny side panel that keeps notes next to whatever page I'm reading. The code was done by Saturday evening. Then came the store listing.

The part nobody plans for

Stores want screenshots in exact sizes: 1280 × 800 here, 640 × 400 there, a marquee tile in yet another ratio. Social posts want 1200 × 627, a carousel wants squares, the README wants something wide. Cropping a full-screen capture by hand never quite hits the numbers, and scaling it makes the text soft.

The fastest way to an exact screenshot is to make the window the exact size first.

So instead of cropping afterwards, I resize the browser window until the visible area matches the format, then capture it 1:1. The core of it is surprisingly small: 

// Grow or shrink the window by the difference to the target
const tab = await chrome.tabs.get(tabId);
const win = await chrome.windows.get(tab.windowId);
await chrome.windows.update(win.id, {
  width: win.width + (1280 - tab.width),
  height: win.height + (800 - tab.height),
});

A checklist for launch day

  • Five screenshots at 1280 × 800, no alpha channel
  • A small promo tile at 440 × 280
  • A privacy policy, even if you collect nothing
  • One clear sentence on why each permission is needed

None of this is hard, but all of it takes time. Plan an afternoon for the listing, and keep the sizes in one place so the next release takes minutes instead of hours.
